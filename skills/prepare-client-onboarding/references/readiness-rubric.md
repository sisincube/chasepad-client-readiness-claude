# ChasePad readiness rubric

The rubric measures evidence available before kickoff. It is not a prediction that a project will succeed.

| Category | Weight | Confirm or inspect | Typical critical blockers |
|---|---:|---|---|
| Project foundation | 10% | objective, business outcome, project type, signed agreement, deposit or first-invoice status when required, source of truth | no approved engagement; a required initial payment is unresolved; no viable objective |
| Stakeholders & ownership | 10% | day-to-day client contact, internal agency owner, decision-makers, final approver, escalation owner | no authorised decision-maker for time-critical work |
| Scope & deliverables | 15% | included deliverables, exclusions, quantities, formats, acceptance criteria, revision boundaries | scope is too ambiguous to begin responsibly |
| Assets & content | 15% | separate asset/file requirements from content/copy requirements; confirm approved brand files, formats, copy versions, product data, references, source footage, legal copy, owners, and due points | required production input prevents the first delivery activity |
| Access & tools | 15% | role-based access, collaborator invites, platforms, environments, analytics, file locations | secure production access is unavailable where work depends on it |
| Approvals & feedback | 15% | what needs approval, named approver, approval method, consolidated feedback owner, approval deadline, stages, sign-off authority, and typical turnaround time | no final sign-off authority or approval path for time-critical work |
| Timeline & dependencies | 10% | kickoff, asset and access due points, review windows, target date, five to eight meaningful milestones, immovable dates, third-party work, client dependencies, and the effect of late inputs | an unmet dependency makes the agreed start impossible |
| Communication & kickoff | 10% | kickoff attendees, meeting date, channels, cadence, response expectations, escalation route, risks, missed-deadline process, and immediate next steps | use rarely; a missing meeting alone is not automatically a blocker |

## Scoring

The renderer applies these values to applicable items:

- Confirmed: 100%
- Clarify: 35%
- Missing: 0%
- Not applicable: excluded from the category denominator

Category scores are averaged, weighted using the table above, and rounded. The overall state is:

- **Ready:** score is at least 85, no missing items, and no critical blocker.
- **Needs attention:** no critical blocker, but the ready threshold is not met.
- **Blocked:** one or more critical items are missing or unclear.

Use enough items to represent the actual project without inflating the denominator. Prefer two to six strong checks per category. Do not create many trivial confirmed items to raise the score.

## Evidence rules

- Cite concise evidence in plain language; do not paste source passages.
- If a named file is mentioned but not supplied, use `clarify`, not `confirmed`.
- A proposed date is not an agreed date.
- A named stakeholder is not necessarily the final approver.
- “Client to provide content” confirms ownership but does not confirm that content is ready.
- A shared password is not acceptable access. Request a secure invitation.
- “Requested” is not the same as “received”; preserve the distinction in evidence and next actions.
- A request is not send-ready merely because the item is named. When known, carry through its owner, due point, requested format, and handoff method.
- Do not penalise a project for irrelevant checks; use `not-applicable` deliberately.
