# Privacy and safety rules

## Data minimisation

- Analyse user-supplied sources in the conversation.
- Send only the structured findings needed for the rendered report to the ChasePad renderer.
- Do not send raw documents, full transcripts, full email chains, or unrelated personal details to the renderer.
- Do not state that source material is stored in ChasePad. The MCP renderer receives only concise structured findings and does not persist project content. Privacy-safe operational analytics contain no project names, brief content, source documents, credentials or conversation text.

## Credentials and secure access

Never ask a client to paste or email:

- passwords;
- API keys or private tokens;
- recovery or backup codes;
- payment-card or bank details;
- identity documents unless the project has a legitimate, user-confirmed need and an approved secure collection process.

Use wording such as:

- “Invite the agency as a collaborator using the platform’s role-based access.”
- “Share access through your approved password manager.”
- “Confirm the account owner and send a secure invitation.”

## Sensitive source content

- Summarise only what is necessary for onboarding.
- Avoid repeating private customer, employee, health, or financial information.
- Flag legal, compliance, or security questions for qualified review rather than presenting a conclusion.
- Do not infer protected or sensitive characteristics about people.

## Accuracy

- Distinguish confirmed evidence, recommendations, and assumptions.
- Do not claim that a project is guaranteed to succeed or launch on time.
- Describe the score as a readiness snapshot based on supplied information.
- Explain that missing information may change the result.
